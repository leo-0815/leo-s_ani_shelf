# 日期回查第一階段

## 範圍
本 PR 僅處理日期優先順序、既有書目回查與同步保護。沒有新增介面、沒有暖機排程，不重新爬全書庫；未包含「已過預定日，待確認」的顯示（第二階段）。

## 行為
- 同商品編號／SKU／ISBN 的商品頁明確出版／上市日期優先，官方出版表只補缺值。一般版、特裝版各自更新，不以系列批次改日期。
- 尖端不再將預購 SellingStartDateTime 視為上市日；不以出版表覆蓋已取得的商品頁上市日。
- 角川處理標題空白、全半形和出貨附註差異，但不從不同書名的推薦商品取日期。
- 青文重讀最後更新的預定出書表及一篇較舊公告，以捕捉原文修改。
- 每次增量更新在各家新書發現後回查既有商品；即使新書發現失敗，仍嘗試日期回查。排程原有 Email／Discord 通知在回查完成後執行，沿用 release_history 和通知去重。
- 已預定（含逾期、遠期與日期未定）以及前後 30 日上市書列為候選。有商品頁連結者才直接回查；只有公告連結的書仍由公告流程更新。
- 五家（角川、青文、尖端、東立、東販）各自每天最多 20 本直接回查。台北日期計算額度；手動更新和 Actions 使用資料庫鎖與持久狀態共用額度。額度是書目數，失敗重試最多兩次 HTTP 嘗試。
- 每秒至多一次直接回查請求，逾 30 日遠期書成功後 7 日再查，其餘 1 日。依最久未嘗試優先，逾期書作次級排序，避免同一批逾期書佔滿額度。
- 停止／崩潰前已保留額度與書目下次檢查時間，最遲下一日重新到期。網路失敗保留資料並記錄錯誤；商品頁沒日期保留原日期並記「未確認」，不當作來源故障通知。
- 新欄位 release_date_source、release_checked_at 與 book_release_checks 由啟動／migrate 自動建立。沒有刪除或重建書籍與個人資料表。
- 商品頁確認日期不接受無確認時間的舊同步資料覆蓋；兩端均為商品頁資料時，以較新的 UTC 確認时间為準。新增欄位可跨雲端／本機傳輸，同步雜湊維持 v1，確認時間不造成每日內容異動。
- 不更改目前日期推算上市狀態的 UI；實際上架確認與日期來源顯示留待第二階段。

## 驗證
- 本機 135 tests，1 個選用 MySQL 測試跳過；雲端 195 tests，4 個選用整合測試跳過。
- 19 個新增回歸測試涵蓋 SQLite 執行真實寫入 SQL：延期、提前、日期異動唯一紀錄、同日不重複紀錄、版本分離、舊出版表／舊 peer 不回蓋、新確認資料能同步、每日額度、到期檢查、錯誤重試、缺日期、五家解析、ISBN 衝突、公告重讀、UTC 日期來源傳输与 v1 雜湊。
- 唯讀實站抽樣：角川、尖端、東立各一筆明確商品日期可解析；青文與東販抽樣商品本身沒有明確日期，保留既有值。沒有寫入真實資料庫或寄通知。
- 可用 python scripts/release_date_smoke.py 作單筆／每家唯讀檢查；加 --diagnostics 顯示日期欄位，不進行大量爬取。需要本機資料庫連線，但不需要新的套件。

## 注意
此回查受每日額度限制，不保證所有書在一天內完成。沒有明確日期的商品不猜日期；商品頁出版時間與出貨註記可能不同，出貨欄位尚未獨立建模。尚未合併或部署，需經人工審核。
