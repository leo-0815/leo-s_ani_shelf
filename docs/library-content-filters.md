# 書目查詢內容分類篩選（PR48／PR50）

分類與偏好分開：偏好決定「可以顯示什麼」，篩選決定「這次想找什麼」。

| 篩選 | 條件 |
| --- | --- |
| 全選 | 只沿用偏好，不額外限制 |
| 一般向 | 沒有正向 BL 標記，而且不是限制級；未知仍可見 |
| BL | 有 `bl_category` 官方標記，可包含同時是 R18 的書 |
| R18 | `content_rating = restricted_18`，可包含同時是 BL 的書 |
| BL＋R18 多選 | BL 或 R18 的聯集，同一本書只出現一次 |
| 清除全部勾選後套用 | 明確選擇零類，結果為零；可再全選恢復 |

介面和出版社一致：勾選、全選、清除勾選，按「套用篩選」才查詢。選單只顯示精簡的「一般向／BL／R18」，不顯示冗長說明或停用選項；點外側或 Escape 關閉時不套用草稿，Escape 返回分類標題焦點。

一般向偏好只顯示一般向；一般向＋BL 顯示一般向及 BL；一般向＋R18 顯示一般向及 R18；全部內容顯示三類。「一般向＋BL」的 BL 篩選仍排除 R18；「一般向＋R18」的 R18 篩選仍排除 BL。改偏好後保留仍允許的選擇，若原選擇全部失效則回到該偏好可見的全部分類，不殘留隱藏篩選。不改任何現有帳號偏好。

API：`GET /api/books?content_filter=bl,r18`，訪客為 `/api/guest/books`。空字串不額外限制；`general`、`bl`、`r18` 可用逗號多選（OR），`none` 表示零類；舊 `bl_r18` 單值交集 API 保留相容，但不在新 UI 列為選項。最多三個不重複分類，空項、未知值與注入字串回應 400。SQL 以固定條件建構，於計數／分頁前套用，與原本可見性及出版社等條件取交集；不能靠修改 URL 繞過帳號偏好。原有查詢限流、成本保護與快取繼續適用，沒有新增查詢、模型或爬蟲，也沒有修改資料表。

UI 僅 Library 顯示此篩選；切換私人訂選或藏書不會暗中沿用 Library 的分類篩選。訪客若透過程式呼叫私人瀏覽器書架，仍以相同正向標記規則在計數／分頁前篩選，不刪除儲存的資料。

目前沒有獨立的逐本男性向／女性向欄位，因此不提供會誤導的空選項，也不把 BL 當女性向、非 BL 當男性向。日後需加入官方逐本分類來源及可追溯證據；未知保持未知。青文出書表的 BOY／GIRL 標籤可作來源之一，但不能將出版社或書系的推測擴大套用到每本書。

測試涵蓋四種偏好 × 單類／多選／零類，登入與訪客 SQL、BL/R18 重疊與去重、未知與輔導級、交叉條件、計數／分頁、無效參數、前端隱藏不允許分類及偏好切換清除失效選擇。
