# PR46：青文出版表與商品的來源對應

本 PR 防止後續新增「出版表一筆、商品頁又一筆」；不批次刪除或合併已存在的重複書目 ID。既有重複整併、來源別名的本機雙向同步、完整缺圖補查留給 PR47。

## 比對與保護

1. 同出版社的精確來源碼優先，其次查 `book_source_aliases` 的舊來源碼。
2. 無精確對應時，只在青文官方出版表／商品來源之間比對；有效 ISBN 相同，或完整書名＋卷次＋媒體＋版本相同且作者有明確交集。僅去除已知媒體前綴、全半形／空白及括號數字的前置零，不用模糊相似度。
3. ISBN 衝突、不同卷、紙本／電子版、標準／特裝版、漫畫／小說不合併。兩個不同商品 SKU 不自動合併；超過 200 個候選或多個符合時保持分開，不任選一筆。
4. 日期不再是身份條件：跨月延後仍可對應同一本書。商品升級出版表時更新原書目 ID，保留出版表舊碼與商品碼的別名。再次爬出版表或舊客戶端上傳舊碼，不重新新增書籍。
5. 已有商品資料時，出版表不能覆蓋已知商品封面、ISBN、連結、定價、日期與精度；商品尚無出版日則仍可用出版表月份作後備，不虛構商品日期驗證時間。商品只有部分作者時保留既有較完整作者名單，出版表可補充包含既有作者的署名。舊 hash 已連到同一官方商品 SKU 時也可升級 canonical 碼，不合併不同 SKU。
6. 分級／BL 仍沿用原有可靠證據、時效與人工鎖定保護。書目 `source_hash` 使用實際保存的 canonical 來源碼；公共同步 hash v1 及 API 格式不變。

同一交易短暫鎖住青文 publisher row，再完成查找、別名保存與書目更新，防止爬蟲與同步上傳用不同來源碼同時新增。別名衝突不重新綁定，整筆交易失敗回滾；不讀寫私人筆記、藏書、訂選或通知紀錄，不更換書目 ID。

## 負荷與範圍

每日青文增量沿用漫畫／小說各三頁、一年窗口、原有停頓；已收錄 SKU 也使用列表既有 JSON 刷新資料，但不增加這些商品的逐本 detail 下載。新 SKU 的商品分級／日期流程照舊。歷史回填仍略過已收錄商品，不重設 checkpoint。

新增 `book_source_aliases` 小型索引表，由既有 `ensure_schema()` 建立；既有資料不重寫、不掃描整家、沒有背景暖機或 AI。候選 SQL 使用 ISBN、標準化書名與出版社／系列索引縮小範圍，最後在 Python 做完整身份檢查。其他出版社的規則不變。

這不是保證所有重複都能識別：缺作者／ISBN、改寫書名、再版或多個候選仍需 PR47 預覽與人工確認。已經有雙來源兩個 ID 時，精確碼繼續更新各自 ID，不在正常爬蟲中自動遷移使用者資料。因此目前《聖母的制裁》的四筆歷史資料不會在本 PR 自動變成兩筆。

本機舊版本上傳已知舊碼可由雲端別名接收，但舊版本 manifest 比對與雲端下載尚不傳別名，來源碼升級後仍可能報差異。PR47 必須一起處理本機來源對應／整併再做一致性驗收；不能宣稱本 PR 已完成本機雙向身份遷移。

## 驗收

- `python -m unittest tests.test_book_identity tests.test_sources tests.test_repository tests.test_release_dates tests.test_catalog_sync -v`
- `python -m unittest discover`
- 本機 MySQL 隔離 SQL：設定 `ANISHELF_TEST_LOCAL_MYSQL=1` 後執行 `python -m unittest tests.test_book_identity_mysql -v`。只允許 localhost；全部使用連線限定 temporary tables，不修改實際書目或帳號。

案例包含出版表先／商品先、跨月延後、舊碼重送、作者格式變更、媒體前綴、卷次／版本／ISBN 衝突、多候選、別名衝突回滾、分級人工鎖定、私人關聯 ID 保留及既有每日頁數不增加。
