## 訪客模式

- 不用 Google 登入也能使用書目、訂選、藏書、追蹤與偏好等核心功能，盡可能維持現有使用體驗。
- 個人紀錄保留在使用者自己的瀏覽器，不混入其他帳號；登入後的合併、退出／共用電腦與備份還原需要另外設計。
- 優先評估 IndexedDB／localStorage 保存書單；Cookie 只適合小量設定或訪客識別，不適合完整藏書（容量有限且會隨請求送出）。
- 訪客 Email 通知不能假定可用：需另外設計收件信箱驗證與必要的伺服器端訂閱，而不是只靠本機 Cookie。

## 安全與防濫用

- 公開／匿名 API 的請求速率、搜尋／推薦／分頁的成本與批次大小限制；避免暴力爬取拖垮免費額度。
- 寫入與管理 API 的登入／角色授權、CSRF、防跨使用者存取；同步 token 不可送到瀏覽器。
- 測試通知的頻率限制、XSS／輸入驗證、安全 Cookie／標頭與可信代理 IP 設定。
- 不用保持暖機解決效能；不承諾能完全阻止公開資料被爬取。限制需兼顧正常使用者與無障礙體驗。
- PR41 為單程序記憶體限流；PR42 的有效簽章訪客身分有獨立配額，簽發仍以實際連線來源限制，未信任可偽造的 X-Forwarded-For。Render 代理下新訪客可能共用簽發額度；多代理的可信來源邊界可另行優化。
- 多實例共享配額、分散式攻擊、匿名訪客大量查詢等更進一步保護另行設計；不宣稱防爬保護能杜絕爬取。
