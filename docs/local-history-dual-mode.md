# 本機歷史書目雙模式

執行 `歷史資料更新.bat`。視窗打開不會連資料庫、抓書或同步，直到手動選擇模式。

- **自動補查系列缺卷**：從本機已有至少兩個數字卷的系列找一般版缺口。每輪最多六個系列，按出版社輪流，不用選系列或貼網址。只補已有最高卷之前的數字缺口，不推定缺卷存在，也不把首刷、特裝、套書或電子書當一般版。
- **地毯式回填**：仍使用既有出版社／年度／分類斷點。有 30 分鐘、1 小時、跑完當前年份或持續執行四種選項。沿用原本的雲端同步，未完成的批次不推進。
- **唯讀預檢**：比對眼前的工具位置、是否有自動找缺卷模組，以及最近一份可讀的 `logs/history-runs/` 報告。沒有報告、沒有分段斷點和無法讀取是不同狀態。只查檔案，不載入資料庫設定、不抓書、不上傳。

地毯式回填時，青文、尖端、東立各自從最新的未完成年度接續；角川、東販沿用原有目錄斷點，每次最多各安排一次。某家來源失敗或斷點未推進，這次不反覆重試，繼續處理其他家。限時或手動停止會停止整輪，不開下一家；雲端同步或工作本身異常仍會明確回報。每次會嘗試在 `logs/history-runs/` 儲存各家工作狀態及前後斷點，供下次預檢查看。報告不是即時進度，未輪到的出版社也不會被標成完成。

## 在升級前核對實際使用的資料夾

可在含新版工具的工作樹執行 `python -B -m app.history_cli --preflight --project-dir "<日常 AniShelf 資料夾>"`。不傳 `--project-dir` 就檢查目前工具所在的資料夾。也可以在新版的歷史選單選 `3`，或用 `歷史資料更新.bat --preflight`。

預檢不安裝、不複製檔案，也不把回填報告當成資料庫的即時斷點。正式回填仍從該安裝設定的資料庫接續。用獨立工作樹做預檢時不用搬 `.env`、本機資料庫或私人資料；日常工作樹有未提交變更時，請先核對相容性再更新，不要強制覆蓋。

系列補查的來源：角川用官方系列分類或書名搜尋（搜尋最多前兩頁，不採舊到新排序，也不把整頁當命中）；尖端讀官方搜尋頁的商品資料；東立從已收錄的單本進入官網套書列表；東販用公開書名搜尋並排除 PURE／會員限定；青文用官方商品搜尋，遭 Cloudflare 攔截就停止。阻擋或限流會讓該出版社暫停一天，不影響其他家，也不代表缺卷已補。

每系列最多查八個商品詳情。只接受能核對同出版社、系列、媒體、缺卷和有效識別碼的一般版。角川折疊的多規格商品要有明確逐卷 ISBN，不會繼承母商品的上市日期、封面、價格或分級。沒有足夠證據就維持未確認。尖端及青文只在官方資料有提供時接受通過檢查碼的台灣條碼。

每系列結束便保存到 `logs/series-backfill.sqlite3`，內含最後查詢時間、尚未核對的卷號和待確認書目。Ctrl+C 可停；下一輪會先查沒查過的系列，不從第一個重來。同一時間只允許一個系列補查。查過僅表示做過有限抽查，不代表系列完整。

待確認清單會保留。輸入 `YES` 才新增到本機，不改既有書目、藏書、訂選或地毯式斷點，也不在這個模式推送雲端。之後另行執行一般書目同步，新增才可能上傳。

## 登入後五分鐘顯示選單

在專案目錄執行 `powershell -File scripts/install_history_logon_task.ps1`。這會為目前 Windows 使用者建立 `AniShelf History Menu` 工作；使用登入而非開機事件，確保能在桌面看見視窗。它只開選單，沒有自動選項。裝好不會補跑本次登入，從下次登入生效。可在工作排程器停用，或以 `Disable-ScheduledTask -TaskName 'AniShelf History Menu'` 停用。移動專案目錄後須重新安裝排程。
