# 多出版社分級補查與每日增量：待實作計畫

2026-10-08 核對現行本機及 cloud/deployment 程式。此文件是計畫，不代表功能已上線。

## 現況

- GitHub Actions 每日台北 08:15 執行 app.scheduled；實際開始時間可能受 GitHub 排程延遲。
- 青文增量新商品會呼叫商品頁分級解析；本機「分級資料補查.bat」也已有青文逐本 checkpoint、重試與同步 outbox。
- 尖端商品詳情解析已有部分「等級：普遍級／限制級」取值，但沒有通用既有書目分級補查。
- 東立、角川、東販尚未接好每日官方分級解析。
- 目前一般向對青文採明確可信普遍級放行；其他出版社主要只排除已知限制級，未知仍可能顯示。
- PR32 是 Server error 修復、PR33/34 是日期功能；原多出版社分級三個 PR 尚未完成。

## 原則

1. 本機補齊歷史分級，雲端每日增量維持新資料分級；不能只靠雲端少量回查補全舊書庫。
2. 只用同 SKU／書號／ISBN 的官方商品規格與可信分類。不能把推薦區、通用成年警示或其他商品分級套到本書。
3. 明確普遍級才放行；無標示、東販「無」、未知／矛盾／抓取失敗保持 unknown，不以書名題材猜成 general。
4. 保存原始標籤、來源、解析器版本與確認時間；保護人工鎖定及較新的分級，舊本機普遍級不能蓋回較新限制級。
5. 不保存封面圖片檔、不引入大型模型、不加暖機；長鴻仍不處理。私人訂選與藏書不刪除。

## 第一個分級 PR（預計 #35，以 GitHub 實際編號為準）

- 把青文本機補查擴充為共用框架，先支援尖端、東立；青文相容保留。
- BAT 可選出版社／多家輪巡，保留 30 分鐘、1 小時、完成目前範圍、持續至停止、唯讀測試。
- 每家以小批次輪巡，不等某家全部爬完才切換。每本結果與 checkpoint 同交易提交。
- 網路錯誤較短期重試、缺明確欄位低頻重试；Ctrl+C 保留已提交的進度，同步失敗留 durable outbox 下次重送。
- 開始前提供版本／同步差異檢查與拉回雲端新書選項，不覆蓋私人資料；分級確認資訊一併同步並保護較新判定。
- 尖端、東立每日新書商品解析也呼叫同一分級規則，不只完成本機 BAT。

## 第二個分級 PR（預計 #36）

- 加入角川、東販；找不到正面普遍級證據就維持未知，明確限制級可記錄。
- 本機輪巡、續跑、同步與每日雲端增量全部覆蓋五家。
- 已下載的商品 HTML 重用解析分級，不為同一本反覆下載；只有公告、沒有可驗證商品頁者先未知。
- 雲端維持台北 08:15 原排程。在通知前完成新資料分級及有限額近期未知補查。
- 建議近期未知分級補查全站每日最多 20 本／最多 10 分鐘、獨立 checkpoint；這是新分級額度，不是日期回查每家 20 本。失敗不讓整個更新或通知流程中止。
- 歷史大量補查仍由本機執行；不在 GitHub 每天重爬整個歷史書庫。

## 第三個分級 PR（預計 #37）

- 一般向統一只顯示可信 general（官方明確欄位或核准人工確認），隱藏其他級別及未知。
- 覆蓋 Library、搜尋、系列列表／詳情、近期上市、訂選、藏書、推薦、商品詳細 API、數量／分頁及通知內容，不能繞過列表從直接連結看到隱藏書。
- 一般帳號預設一般向，尊重已保存偏好；管理者偏好不重設。
- 自建私人藏書不自動猜分級、不進入公用字典；一般向下未知先隱藏，取消一般向可再看到，資料不刪除。
- 切換前提供各家普遍級／限制級／未知覆蓋率摘要。未知較多會暫時使可見書數下降，這是保守過濾，不是遺失資料。

## 每個 PR 的驗收

- 新增／歷史補查共用解析器，普遍級、限制級、未知、矛盾欄位、SKU不符、不同版本、網路失敗都有測試。
- 抽樣官方頁面：普遍級、限制級及未知各取數筆；隨機檢查判成普遍級的商品封面／簡介是否矛盾，有疑慮不放行。
- 實際資料庫查詢、checkpoint 中斷重跑、同步失敗重送、較新 R18 不被舊 general 覆蓋，人工鎖定不動。
- CI 與每日排程同入口測試：新書確實保存 restricted_18／general，不只是能手動補查。
- 本機／雲端兩版本分開保存，README 更新，PR CI 通過後按授權合併部署並驗收；不得用日期 PR 完成冒充分級 PR 完成。

狀態：三項均待實作，等待確認本計畫；本次沒有執行爬取或修改正式資料。
