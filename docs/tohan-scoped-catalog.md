## 範圍與資料保護

- 清單只解析 `tab-pane active gobal-warp` 主要商品區中的商品卡片。不抓整頁所有連結，不採推薦區、廣告或隱藏分頁。
- 同一 source ID 去重並合併官方分類證據。漫畫／小說證據衝突保持未知、報錯，不猜。
- 商品頁自身 title 分類優先；官方分類為一般書籍直接排除。書名含「小說」、全站導覽含「BL」都不構成單本類型／分級證據。
- 商品頁還須具有單本作者／ISBN 欄位，不能把 HTTP 200 的登入頁、服務錯誤頁當成書名保存。
- 只讀到清單的型別記號不新增 DB 欄位；保存時保護完整商品 metadata。只有既有 unknown 類型能用可靠清單補成漫畫或小說；不以清單覆寫既有已分類資料。
- 清單種子不將商品補查標記成功；會員限制與 HTTP 故障仍保留待補。未知分級不等同普遍級，也不因登入限制推定 R18。
- 不刪任何書目，不修改藏書、訂選、系列追蹤或帳號，不自動清理舊資料。
- 一般爬取／日期回查不直接改動既有 manga/novel 類型，即使新解析發現不符，也先保留系列分組。unknown 可依可靠證據提升；已分類舊資料須經審核並處理系列追蹤相容性後再批次修正。同步入口不額外禁止經審核的類型修正。

## 舊資料只讀盤點

`python -m app.tohan_scope_audit --limit 20`

或手動 GitHub workflow 選 `test_publisher_only=tohan_audit`。只 SELECT 公共書目，讀官方單本分類並列出 same／type_mismatch／out_of_scope／needs_review／requires_login／fetch_error；不寫入、不執行 schema migration、不寄通知。最多 100 筆，預設 20 筆、單次請求不自動重試。

`out_of_scope` 是人工修正候選，不是刪除指令；未知、會員限制及下載失敗不當作已確認的誤分類。既有資料修正需另行審核。
