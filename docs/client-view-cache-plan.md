## PR52 前的現況

- `web/app.js` 的 `apiInflight` 只合併尚未結束的相同 GET；完成後即移除，沒有登入使用者的一般查詢結果快取。
- `switchView()` 回到書目、訂選、藏書、系列、近期上市、推薦及設定時，仍會呼叫對應載入函式。
- 出版社與統計有首次共用的 `catalogPromise`，所以並非每次切頁都重載所有資料。
- 訪客另有約 30 秒公共查詢快取；首頁的 generation 用於避免舊請求覆蓋，不是結果快取。
- 書目、訂選、藏書、系列及近期上市共用 browse 類別的每分鐘 20 次限制；另外有以查詢成本計算的資源預算。不能將一次點擊等同一次單獨額度。
- 目前伺服器共享公共回應快取僅供訪客白名單公共資料使用；不能直接把含登入使用者書架狀態的回應放進公共快取。

## PR52：使用者切頁快取與精準更新

1. 依使用者最新決定，不做登入時的全頁預載。保留登入只載入首頁、第一次點進其他頁面才載入該頁所需資料；已載入列表、頁碼、搜尋、篩選與捲動位置各自保存，切回時立即還原。不預先下載未開啟頁面、整個書庫、所有分頁、每本書/系列詳情或完整匯出。
2. 優先使用單一分頁的記憶體快取，不把 Google 帳號的私人書架、筆記或訂單新增存到 Cookie/localStorage；重新整理可重新取得資料。現有訪客 IndexedDB 的資料保存用途不變。
3. 查詢快取鍵必須包含登入帳號/訪客識別、登入世代、內容偏好、端點、正規化查詢參數、出版社、多選分類、排序、分頁及頁大小。書目、訂選與藏書即使用相同端點也不能混用結果。
4. 每份查詢結果載入完成後，各自進入 5 分鐘新鮮期，出版社等少變資訊可維持 15 分鐘；上限約 30 個查詢或 8 MB，採 LRU 淘汰。五分鐘是有效期限，不是每五分鐘自動全站重載：之後僅在實際使用過期頁面、資料變更或使用者要求時更新，不因有人瀏覽就自動為 Render 暖機或啟動輪詢。
5. 命中有效快取要在 cooldown 判斷前處理：被限流不應阻止使用已載入內容。過期或離線時可暫留舊內容，但不得跨帳號/偏好使用；僅在確有過期/刷新失敗時顯示簡短提示與重試操作，不為每個正常頁面增加快取說明文字。
6. 保留相同 GET 的 in-flight 合併；加入頁面/查詢世代檢查，舊搜尋或舊頁回應不得覆蓋新頁。快速導航只載入最後仍需要的頁面；不隨意取消其他消費者仍共用的請求。
7. 寫入成功後局部更新目前可安全對應的狀態，並標記相關快取失效。不能把 POST/DELETE 快取成成功，也不能清空所有頁面再同時重載。
8. 新鮮期過後只在實際使用頁面或需要時更新；提供清楚的重新載入操作，不把管理者「爬取出版社更新資料」和「重新讀取目前頁面」混成同一按鈕。
9. 登出、換帳號、訪客/Google 切換必須清除相關記憶體並隔離舊請求。內容偏好變更立即清除舊可見範圍的結果；同瀏覽器跨分頁可用 BroadcastChannel 廣播失效，不傳送私人資料。恢復分頁時視節流與過期狀況驗證登入/偏好，避免每次切內部頁面都查一次。

### 按需載入的邊界與保護

- 先確認登入、角色與內容偏好，再使用對應快取。一般帳號不請求管理者頁，訪客不請求 Google 帳號私人或管理功能。
- 未開啟的頁面不發出預載請求；不靠依序切換/渲染所有頁面建立快取。
- 第一次進頁的請求沿用合併、限流與成本保護，失敗只影響該頁；不能因為其他尚未開啟的頁面故障而卡住登入。
- 載入期間若退出登入、切換帳號或偏好，舊請求結果不得回填到新的使用者狀態。

### 驗收

- 在合成資料環境確認登入不預載尚未開啟頁面，也不載入全書庫/所有分頁或執行寫入；首次開啟書目、系列、訂選後，30 次快速來回切換，在有效期內不再產生相同列表 GET，且保留篩選及捲動。
- 一般帳號/管理者/訪客分別驗收瀏覽/metadata 類別配額與加權成本預算，測試單頁失敗、限流等待與中途退出登入，不能造成永久登入卡住或跨帳號回填。
- 加入訂選、購入藏書或追蹤系列後，相關頁面、標記與數量一致；只刷新依賴項，不形成連鎖重載。
- 測試有效/過期快取、錯誤、限流、離線、同時請求、回應順序顛倒、帳號切換、偏好切換、跨分頁失效及容量淘汰。
- 不快取錯誤回應、CSRF token 或其他帳號的私人結果；快取物件不因某個畫面修改而污染別的查詢。
- 正式站僅少量正常導覽驗收；不在正式站用大量循環請求測試限流。

### 大型系列追蹤（使用者補充）

「每分鐘 20 次 API 操作」不能誤當成「一個系列最多 20 本」。目前 Google 帳號的 `/api/series/follow` 是一次 POST，`series_follow.set_follow()` 使用集合式 `INSERT ... SELECT`，沒有 `LIMIT 20`；一個 100 本的系列不是 100 次追蹤請求。這個行為應維持，而不是把資料任意截在 20 本。

訪客的 resolve 則是每批最多 20 個系列、每頁 200 筆書目，兩者也不代表單系列只准 20 本。現有訪客載入有頁數與儲存量安全界線；超大型系列必須清楚區分「追蹤設定已保存」與「書目尚在補齊」，不可提示已完整完成但默默截斷。

PR52 一併驗收 100／300／1,000 筆書目的系列：一次追蹤操作涵蓋符合範圍的全系列、跨頁可補齊、重複操作不重複新增，不覆蓋預購/筆記/優先度，已收藏書籍不重新加入想買。維持小說/漫畫分開及偏好規則。登入版保留集合式寫入；訪客需要多次內部讀取時，應合併請求、節流並保存續查位置，遇到限流保留進度，不要求使用者重做整個追蹤動作。

## 反爬蟲的界線

本機快取命中時可完全不發 API，因此不增加這次導航的後端/資料庫請求或限流計數。但直接打 API 的爬蟲不會遵守前端快取，仍消耗 Render 連線、CPU/流量，未擋住的請求也可能查資料庫。

保留既有伺服器身份/來源限制、每分鐘類別限流、成本預算、參數/分頁上限、併發保護及公共快取。先用前端改善量測誤傷，不直接取消限流或假設 Cookie/前端可辨識真人。HTTP 304/ETag 仍是網路請求，也不等於沒有驗證或資料庫成本。

若後續仍需降低爬蟲資料庫負荷，再獨立評估「不含私人欄位的公共書目快取＋個人狀態覆蓋」。不可把完整登入回應跨帳號共享，也不為此引入付費服務或保活輪詢。
